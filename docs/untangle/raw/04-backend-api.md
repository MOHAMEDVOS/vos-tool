# backend-api — Problems (Step 2)

Scope: `backend/api/*.py` only (17 files: `__init__.py`, `auth.py`, `audio.py`, `dashboard.py`,
`health.py`, `jobs.py`, `phrases.py`, `quota.py`, `readymode.py`, `readymode_users.py`,
`reports.py`, `scoring.py`, `settings.py`, `sharing.py`, `system.py`, `tl_actions.py`,
`user_data.py`). Read-only analysis, no fixes proposed. Findings inside `auth.py` (Google OAuth +
JWT, protected per project CLAUDE.md) are prefixed `[PROTECTED]`.

## Hidden Links

- `backend/api/reports.py:48`, `backend/api/quota.py:33,39,48,69,75`, `backend/api/sharing.py:33,38,90,95`, `backend/api/system.py:30,36,41`, `backend/api/settings.py:77,342,371`, `backend/api/phrases.py` (most handlers) — the project convention (`{"success": true/false, "data"/"error": ...}`, stated in this project's CLAUDE.md) is not enforced anywhere: a grep for a literal `"data"` response-wrapper key across all 16 route files returns zero hits (the only `"data"` match, `readymode.py:336`, is an unrelated SSE event dict), and `"success"` appears in only 5 places total. No custom exception handler is registered for `HTTPException` (`backend/main.py` only registers a catch-all for bare `Exception`, returning `{"detail": "Internal server error"}`), so every one of the ~90 `raise HTTPException(...)` calls across this directory returns FastAPI's default `{"detail": ...}` shape, not the project's convention. Every handler has to know and follow the convention by hand, and almost none do.

## Special Cases

- `backend/api/health.py:25-40,51-65,76-90,104-122,133-160,171-186` — all 6 endpoints in this file follow the same broken shape: a deliberate `raise HTTPException(503, "... not available")` for a missing monitor, inside a `try` block whose own `except Exception as e:` catches that same `HTTPException` (it subclasses `Exception`) and re-raises it as a generic `HTTPException(500, f"... error: {e}")`. The intended 503 + message never reaches the caller in any of the 6 cases — a swallowed exception, repeated six times.
- `[PROTECTED] backend/api/auth.py:87,107` — `if email.lower() == "mohamedibrahimpayonner@gmail.com":` is a literal if-branch for one specific person, appearing twice in the same function.
- `backend/api/settings.py:225` — `if target_username == "Mohamed Abdo":` is a second, independent if-branch for one specific account (see also the Hidden Links entry on this pair — not confirmed whether it's reachable given usernames elsewhere are emails).
- `[PROTECTED] backend/api/auth.py:30-77` — `google_login` branches its entire verification path on which of two mutually-exclusive request fields (`credential` vs `access_token`) happens to be present, rather than an explicit discriminator; one path verifies a signed JWT locally, the other calls out to Google's `tokeninfo`/`userinfo` endpoints over plain `requests`.
- `backend/api/readymode_users.py:46-93` (`/create`) is reachable by any authenticated user (`Depends(get_current_user)`) while its three siblings `/delete`, `/duplicates`, `/inactive` (lines 99,167,220) all require `Depends(get_current_admin_user)`; the code's own docstring (lines 101-105) says this is intentional and "relies on the frontend hiding its tab from non-admins."
- `backend/api/dashboard.py:173-185` (`get_campaigns_list`) catches any exception from `get_available_campaigns` and silently returns `[]`, while every other handler in this same file converts the same kind of failure into a 500. One quiet failure path among the rest being loud.

- `[PROTECTED] backend/api/auth.py:246-257,260-294` and `backend/api/tl_actions.py:132-151` (`podio_callback`) both return `RedirectResponse`/`HTMLResponse` instead of JSON — a response-shape special case for the two OAuth-popup callers, departing from the rest of the directory's (nominally JSON) responses.
