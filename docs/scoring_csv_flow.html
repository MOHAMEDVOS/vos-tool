HTTP Client
readymode_http

3 · Four HTTP calls to ReadyMode — this is the CSV mechanic

  1. Login. GET / (seed cookies) → POST /login_new with browser headers + logout_other_sessions=on. → gets the stationId cookie = logged in.
  2. Read disposition map. POST /CCS Reports/call_log (init_call_log). → this dialer's own ids: Wrong Number=5, Decision Maker-NYI=2.
  3. Seed the filter. GET /CCS Reports/call_log/update?report[...] with date + those 2 disposition ids. → sets the session's report filter on the server. Decides WHICH rows.
  4. Download CSV. POST /CCS Reports/call_log/ExportMenu/CL.csv body fieldList[keys][]=CCS_Profile.phone & u.u_name. → returns CSV bytes. Decides WHICH columns. Rows come from step 3's filter.

5 · Add flagged calls + cache under run_id

get_flagged_calls (your audit data, same date) → flagged index. Both maps saved in Redis under a run_id (1h). SSE emits done with the counts.

The one trick to remember: CL.csv carries no filter of its own. It just returns whatever the session filter was set to in step 3 (/update). So /update decides the rows, CL.csv decides the columns. That's why we always seed the filter right before downloading.
What happens next (separate clicks): you paste agent names → /generate reads the cached maps by run_id (no re-pull) → for each agent: flagged numbers if any, else 5 random from their busiest dialer → table. Optional /export-sheet → Google Sheet.
